# ValutaTrade Hub

ValutaTrade Hub — проект на Python, реализующий консольное приложение
для управления виртуальным валютным портфелем и симуляции торговли валютами.

## Технологический стек

- Тип приложения: CLI (консольное приложение)
- Язык программирования: Python 3.14
- Управление проектом, зависимостями и сборкой: uv, uv_build
- Ввод и разбор команд: prompt, shlex
- Формирование таблиц: PrettyTable
- Хранение пользователей, портфелей и кеша курсов: JSON
- Работа с файлами и путями: pathlib, tempfile, os
- Работа с датами и временем: datetime, UTC
- Хеширование паролей: hashlib, PBKDF2-HMAC-SHA256
- Организация кода: ООП, разделение моделей, бизнес-логики и CLI
- Проверка качества кода и форматирование: Ruff
- Контроль версий: Git

## Установка

```powershell
uv sync
```

## Запуск

```powershell
uv run project
```

Приложение принимает команды в цикле. `help` показывает синтаксис,
`exit` завершает работу. Значения с пробелами должны быть заключены в кавычки.

## Регистрация и вход

Пользователи сохраняются в `data/users.json`.
При регистрации создаётся портфель с USD-кошельком, после чего нужно отдельно выполнить вход.

### Доступные команды (без регистрации)

| Команда | Описание |
|---|---|
| `register --username <имя> --password <пароль>` | Зарегистрировать пользователя |
| `login --username <имя> --password <пароль>` | Войти в систему |
| `get-rate --from <валюта> --to <валюта>` | Показать прямой и обратный курсы и время обновления |
| `help` | Показать справку по всем командам |
| `exit` | Завершить работу программы |

### Пример использования

Пример для нового хранилища без пользователей:

```text
> register --username alice --password 1234
Пользователь 'alice' зарегистрирован (id=1). Выполните login для входа.

> login --username alice --password 1234
Вы вошли как 'alice'

> login --username alice --password wrong
Ошибка: Неверный пароль

> get-rate --from USD --to BTC
Курс USD→BTC: 0.00001667 (обновлено: 2026-11-01 12:00:00)
Обратный курс BTC→USD: 60000.00

> get-rate --from EUR --to BTC
Курс EUR→BTC: 0.00001800 (обновлено: 2026-11-01 12:00:00)
Обратный курс BTC→EUR: 55555.56
```

- Имя должно быть непустым и уникальным с учётом регистра.
- Новый пароль должен быть строкой длиной не менее четырёх символов.
- Пароли хранятся как PBKDF2-HMAC-SHA256 хеши с индивидуальной случайной солью, 100 000 итераций.
- Новый успешный `login` заменяет текущую сессию; неудачный вход сохраняет предыдущую.
- Регистрация нового пользователя разрешена во время текущей сессии и не
  переключает аккаунт. Для переключения выполните `login` с другими данными.
- `exit` завершает приложение, отдельной команды выхода из аккаунта пока нет.
- Время курса в CLI выводится в UTC в формате `ГГГГ-ММ-ДД ЧЧ:ММ:СС`.
  В JSON сохраняется ISO-формат.
- Для `get-rate` обязательны оба аргумента: `--from` и `--to`.
- Коды валют должны быть непустыми строками и приводятся к верхнему регистру.
- Исходная и целевая валюты могут отличаться от USD.
- Отсутствующие или устаревшие курсы обновляются из заглушки. Если необходимого курса нет ни в свежем кеше, ни в заглушке,
  выводится сообщение об ошибке.
- Курсы округляются только при выводе.

## Управление портфелем и торговля

Покупка, продажа и просмотр портфеля доступны после входа.
Балансы сохраняются в `data/portfolios.json` и восстанавливаются
при следующем запуске приложения.

### Доступные команды (зарегистрированным пользователям)

| Команда | Описание |
|---|---|
| `show-portfolio [--base <валюта>]` | Показать кошельки и итог в выбранной валюте; по умолчанию USD |
| `buy --currency <валюта> --amount <количество>` | Купить указанное количество валюты за USD |
| `sell --currency <валюта> --amount <количество>` | Продать указанное количество валюты за USD |

### Пример использования

После регистрации и входа:

```text
> show-portfolio
> buy --currency BTC --amount 0.05
> sell --currency BTC --amount 0.01
> show-portfolio
> show-portfolio --base EUR
```

При учебном курсе 60 000 USD за BTC покупка 0.05 BTC списывает 3 000 USD,
а продажа 0.01 BTC зачисляет 600 USD. Из начальных 10 000 USD остаётся
7 600 USD и 0.04 BTC. Общая стоимость при том же курсе равна 10 000 USD.

- Коды валют приводятся к верхнему регистру. Количество валюты в `--amount`
  должно быть положительным конечным числом и обозначает единицы валюты,
  а не сумму в долларах.
- Портфель выводится таблицей `PrettyTable` с итогом в выбранной базе.

## Модель торговли

Выбрана полная модель, разрешённая уточнениями преподавателя:

- При регистрации создаётся USD-кошелёк с 10 000 виртуальных USD.
- `buy` списывает `amount × rate` USD и зачисляет `amount` купленной валюты.
- `sell` списывает `amount` валюты и зачисляет выручку в USD.
- При нехватке USD или продаваемой валюты сделка отклоняется.
- Новый валютный кошелёк создаётся автоматически при первой покупке.
- USD служит расчётной валютой; `buy --currency USD` и `sell --currency USD`
  отклоняются. Дополнительной команды пополнения нет.
- Оба баланса сохраняются вместе в одной записи портфеля. Остальные
  пользователи не затрагиваются. Комиссии не учитываются.

Балансы хранятся как `float`. При полном снятии допускается абсолютное
расхождение с остатком до `1e-12` единиц валюты включительно; такой остаток
обнуляется. Это учитывает погрешности вроде `0.3 - 0.1`, а не разрешает
произвольный перерасход. С нулевого баланса снять средства нельзя.

Стартовый баланс задан настройкой `initial_usd_balance` в секции
`[tool.valutatrade]` файла `pyproject.toml`.
При вызове из Python его можно переопределить параметром `initial_balance`
функции `register()`. В CLI такого флага пока нет. Ранее созданным
пользователям стартовый баланс автоматически не начисляется.

## Работа с кешем

`get_rate()` возвращает неокруглённый курс и ISO-строку времени обновления.
Округление применяется только при выводе. Для конвертации используются
курсы к USD: `FROM_TO = FROM_USD / TO_USD`, для USD курс равен 1.

В текущей части `data/rates.json` имеет плоский формат:

```json
{
    "EUR_USD": {
        "rate": 1.08,
        "updated_at": "2026-11-01T12:00:00+00:00"
    },
    "source": "Stub",
    "last_refresh": "2026-11-01T12:00:00+00:00"
}
```

TTL по умолчанию равен 300 секундам и задаётся настройкой
`rates_ttl_seconds` в секции `[tool.valutatrade]` файла `pyproject.toml`.
Отсутствующий или устаревший нужный курс обновляется из `EXCHANGE_RATES`
в `core/models.py`. Коды проверяются по реестру `core/currencies.py`:
сейчас в нём USD, EUR, RUB, BTC и ETH. Наличие пары в кеше само по себе
не добавляет валюту в реестр.
Если нужного курса нет ни в свежем кеше, ни в заглушке, команда сообщает
об ошибке. Повреждённый JSON не подменяется пустым хранилищем.

## Модель валют

В `core/currencies.py` определён абстрактный класс `Currency` с методом
`get_display_info()`. `FiatCurrency` добавляет страну или зону эмиссии,
`CryptoCurrency` — алгоритм и капитализацию. Название не может быть пустым;
код приводится к верхнему регистру и должен содержать 2–5 символов без пробелов.
Капитализация должна быть конечным неотрицательным числом.

`get_currency(code)` возвращает объект из реестра, а для неизвестного кода
выбрасывает `CurrencyNotFoundError`. Usecases проверяют валюты через эту функцию.
Нулевые капитализации в реестре являются учебными заглушками.

## Настройки и JSON-хранилище

`SettingsLoader` из `infra/settings.py` читает секцию `[tool.valutatrade]`
файла `pyproject.toml` и кеширует настройки. `get(key, default)` возвращает
значение, `reload()` перечитывает конфигурацию. При отсутствии секции
или некорректных обязательных значениях выводится ошибка.
Проверки настроек логирования выполняются при загрузке: имя файла без каталога,
уровень INFO/DEBUG, форматы записи и времени, размер файла и число архивов.
При неудачном `reload()` ранее загруженные настройки сохраняются.

| Настройка | Назначение |
|---|---|
| `users_file`, `portfolios_file`, `rates_file` | Пути к JSON; относительные пути отсчитываются от корня проекта |
| `rates_ttl_seconds` | Время актуальности курса в секундах |
| `default_base_currency` | База для `show-portfolio`, если `--base` не указан |
| `initial_usd_balance` | Стартовый виртуальный баланс нового пользователя |
| `logs_dir`, `log_level`, `log_format` | Каталог, уровень и формат логирования |
| `actions_log_filename` | Имя файла лога; при отсутствии — `actions.log` |
| `log_date_format` | Формат времени UTC: `%Y-%m-%dT%H:%M:%S+00:00`; используется и по умолчанию |
| `log_max_bytes`, `log_backup_count` | Размер файла лога и число архивов |

Usecases работают с JSON через `DatabaseManager` из `infra/database.py`.
`read()` читает хранилище, `write()` атомарно заменяет один файл,
`update()` последовательно выполняет чтение, преобразование и запись.
Приложение рассчитано на последовательное выполнение команд в одном потоке;
параллельная запись из нескольких потоков или процессов не поддерживается.
При сбое сохранения портфеля регистрация пытается отменить запись пользователя;
аварийное завершение между двумя записями всё ещё может потребовать восстановления.

Оба класса реализуют Singleton через `__new__`: повторные вызовы возвращают
тот же экземпляр без повторной инициализации. Импорт модулей сам по себе
не создаёт экземпляры. Usecases используют пути, TTL, базу и стартовый баланс;
`logging_config.py` использует настройки логирования.

## Логирование операций

К `buy()` и `sell()` применяется декоратор `@log_action` из `decorators.py`.
Он сохраняет записи через стандартный модуль `logging`. Каталог и имя файла
задаются через `logs_dir` и `actions_log_filename`; по умолчанию — `logs/actions.log`.
Логгер настраивается при первой операции; повторные вызовы не добавляют
дублирующие обработчики. Каталог `logs/` исключён из Git.

Выбран человекочитаемый строковый формат: уровень, ISO-время UTC,
далее поля `ключ=значение`. Строковые значения заключаются в кавычки,
переводы строк экранируются. Например:

```text
INFO 2026-11-03T12:00:00+00:00 action="BUY" user_id=1 currency_code="BTC" amount=0.05 rate=60000.0 base="USD" before=0.0 after=0.05 usd_before=10000.0 usd_after=7000.0 result="OK"
```

Обязательные поля: `action`, `user_id`, `currency_code`, `amount`, `rate`,
`base`, `result`. При ошибке добавляются `error_type` и `error_message`;
ещё не полученные значения остаются `null`. Исключение записывается на
уровне INFO и пробрасывается дальше в CLI без замены.

При `verbose=True` в успешную запись добавляются `before`, `after`,
`usd_before`, `usd_after`. При нехватке средств в ошибочную запись
добавляются `available` и `required`. При `verbose=False` этот контекст
не записывается. Сейчас подробный режим включён для обеих торговых операций.
Регистрация и вход пока не декорированы; аргумент пароля не записывается.

Уровень по умолчанию — `INFO`. Для отладки установите `log_level = "DEBUG"`
в `[tool.valutatrade]` и перезапустите приложение. Записи операций остаются
на уровне INFO и при включённом DEBUG.

Используется `RotatingFileHandler`: при достижении 1 МиБ активный файл
ротируется, сохраняется до трёх архивов (`actions.log.1`–`actions.log.3`).
Параметры задаются через `log_max_bytes` и `log_backup_count`.
Логи не выводятся в консоль; результат или ошибку пользователю показывает CLI.

## Ошибки команд

Доменные исключения возникают в моделях и usecases и перехватываются в CLI.
После сообщения об ошибке приложение продолжает принимать команды.

| Команды | Исключение | Поведение CLI |
|---|---|---|
| `buy`, `sell` | `InsufficientFundsError` | Показать доступную и требуемую сумму; портфель не изменяется |
| `buy`, `sell`, `get-rate`, `show-portfolio` | `CurrencyNotFoundError` | Сообщить о неизвестной валюте и предложить `help get-rate` |
| Команды, получающие курсы | `ApiRequestError` | Показать причину, предложить повторить позже и проверить сеть |

Для неизвестной базы портфеля выводится `Неизвестная базовая валюта 'ABC'`.
Неизвестная валюта отличается от отсутствующего курса: первая не входит
в реестр, а для второй валюта известна, но источник не вернул данные.
Пока внешние API не подключены, `ApiRequestError` может возникнуть при
отсутствии или некорректности курса в учебной заглушке. Ошибки JSON и
файлового доступа обрабатываются отдельно, без сообщения о сбое сети.

```text
> help get-rate
get-rate --from <валюта> --to <валюта>
Показать прямой и обратный курсы валют и время обновления.
Поддерживаемые валюты: BTC, ETH, EUR, RUB, USD
```

## Демонстрация работы
